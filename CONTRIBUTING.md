# Contributing

Thanks for your interest in `consult-mcp-server`. This is a small project; the
fastest path is usually to **open an issue first** with the problem you're
trying to solve, then we can agree on shape before you write code.

## Dev setup

```sh
git clone https://github.com/irwin-r/consult-mcp-server
cd consult-mcp-server
uv venv
uv pip install -e ".[dev]"
cp .env.example .env   # then fill in at least one provider key
```

## Running tests

```sh
uv run pytest -v                  # full suite
uv run pytest tests/test_smoke.py # smoke only
```

Live tests are gated on provider API keys — they skip cleanly when absent.
The offline tests must always pass.

## Linting

```sh
uv run ruff check
uv run ruff format
```

Optional but encouraged: install the pre-commit hooks.

```sh
uv run pre-commit install
```

## What we'll accept

- **Bug fixes** with a reproducing test.
- **New model providers** that LiteLLM doesn't already cover. Adding a new
  registry alias for a LiteLLM-supported model is a one-line change in
  `consult/config/models.json` — please include the `privacy_tier` field.
- **New capsule kinds** (beyond `decision` / `review` / `research`) — keep
  them small, schema-defined, and add an entry to the discriminated union
  in `consult/types.py`.
- **Documentation** improvements.

## What we'll usually decline

- New top-level MCP tools. The five we have (`consult`, `panel`, `refine`,
  `sequence`, `synthesise`) cover the design space; new ones bloat the
  agent's tool-picker prompt without earning their keep.
- Backwards-compat shims for our own pre-1.0 schema changes.
- Web UIs or HTTP transports. The library is reusable for both; we don't
  want to maintain them here.

## Code style

- Python 3.11+ (`from __future__ import annotations` everywhere).
- Pydantic v2 for any data crossing a boundary.
- `StrictModel` (from `consult.types`) instead of bare `BaseModel` — silent
  field drops are a known footgun.
- No comments that just narrate what the code does. Comments should
  explain *why* — invariants, hidden constraints, past incidents.
- No `# Generated by …` attribution. No emoji unless asked.

## Dependencies

`litellm` is the security boundary for every outbound call and ships frequent
breaking changes, so it is pinned to a tight range (`>=1.83,<1.90`) and bumped
by hand, never floated by Dependabot. When you bump it, widen the pin in
`pyproject.toml`, run `uv lock --upgrade-package litellm`, then run the full
suite and `uv run pip-audit --skip-editable` before merging. A live run
against the real providers is the final check, since the suite mocks
`litellm.acompletion`. `mcp` and `pydantic` follow the same hand-bump rule.

## Releasing

Maintainer-only. Tag a release on `main`; `release-please` opens a release PR.
Merging that PR publishes to PyPI (via OIDC trusted publishing) and pushes a
Docker image to GHCR.
